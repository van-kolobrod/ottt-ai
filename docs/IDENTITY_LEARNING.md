# Адаптация критериев идентичности: эксперимент 5Б

Модули [`identity_data.py`](../experiments/memory/identity_data.py) и [`identity_learning.py`](../experiments/memory/identity_learning.py) создают размеченные синтетические последовательности и подбирают ограниченную конфигурацию неизменённого алгоритма 5А. Это обучение по независимой контрольной разметке генератора, а не по собственным предположениям трекера.

## Разметка и воспроизводимость

`generate(seed)` возвращает семь сценариев: движение, увеличение размера, изменение формы, временное исчезновение, одинаковые объекты, неразличимый обмен местами и контрольную замену объекта. Последний сценарий проверяет риск ложного объединения: похожий изменившийся сигнал в действительности принадлежит новому объекту.

Публичный кадр содержит только ASCII-поле и временную метку. `extract_components()` получает только поле, а `match_components()` — только компоненты существующего восприятия, временной интервал и конфигурацию. Скрытые контрольные ID и списки занятых ими ячеек находятся в отдельном поле разметки последовательности. Оценщик обращается к ним после получения обычного сопоставления, проверяя принадлежность ячеек компонентов. Объекты связны, не перекрываются, не сливаются и не разделяются.

Постоянный seed воспроизводит поля, размеры, смещения и контрольную разметку. По умолчанию:

| Часть | Seeds | Последовательности |
|---|---|---:|
| Обучающая | 11, 23, 37 | 21 |
| Валидационная | 101, 103 | 14 |
| Тестовая | 211, 223, 227 | 21 |

Seeds строго не пересекаются. Семь семейств сценариев общие для всех частей; проверяются новые реализации тех же синтетических шаблонов. Это **не проверка обобщения на неизвестные классы объектов или новые типы сценариев**. Генератор использует фиксированные размер поля, диапазоны трансформаций и времена; эти ограничения заданы разработчиком.

Неоднозначный обмен размечен генератором отдельно: оставление одинаковых объектов на местах и обмен между кадрами дают одинаковый сигнал. Контрольная разметка знает реализованный вариант, но сам сигнал не выделяет его. Обоснованность неопределённости определяется этим независимым сценарием, а не альтернативами, созданными оцениваемым алгоритмом.

## Подбор параметров

Перебираются 18 конфигураций только трёх действующих параметров 5А:

- `max_speed`: 2, 3, 5 ячеек/с;
- `max_area_change`: .6, .8;
- `max_shape_change`: .6, .8, .9.

Базовая конфигурация 5А обязательно включена. Остальные параметры и веса стоимости остаются исходными. Каждый кандидат оценивается на обучении. Среди кандидатов с минимальной обучающей потерей валидация выбирает меньшую потерю; при равенстве предпочтительны меньшее число изменённых параметров и затем канонический порядок конфигурации. Тестовые данные передаются только в последующее сравнение: `fit(training, validation)` вообще не принимает тестовый набор.

Найденные параметры не заменяют `identity.DEFAULT_CONFIG`. Для применения нужно явно передать `track(memory, frame_ids, result['selected_config'])`.

## Метрики и асимметрия

Единица оценки — соответствие пары компонентов соседних кадров. Истинная пара имеет одинаковый контрольный ID. Измеряются:

| Поле | Смысл |
|---|---|
| `correct_matches` | Поддержанное соответствие с одинаковыми контрольными ID |
| `false_matches` | Поддержанное соответствие с различными контрольными ID |
| `missed_correspondences` | Все истинные пары без поддержанного соответствия |
| `missed_decisive` | Истинная пара отвергнута как `different_entity` |
| `justified_unknown` | Истинная пара имеет `unknown_identity` в независимо размеченном неоднозначном переходе |
| `avoidable_unknown` | Истинная пара имеет `unknown_identity` вне такого перехода |
| `unknown_negative_pairs` | Неопределённые пары с различными контрольными ID; вспомогательная метрика |

`missed_correspondences = missed_decisive + justified_unknown + avoidable_unknown`.
Функция потерь: `10*false_matches + missed_decisive + .5*avoidable_unknown`. Обоснованная неопределённость не штрафуется. Таким образом, отказ предпочтительнее ошибочного объединения, а верное соответствие лучше необоснованного отказа. Коэффициенты потерь выбраны разработчиком, не обучены.

`avoidable_unknown` — условное название показателя этого размеченного бенчмарка. Наличие единственной контрольной пары само по себе не доказывает её восстановимость по сигналу. Особенно это важно для внешне похожих роста и замены объекта: истинная история различна, а наблюдаемые признаки могут совпадать. Метрики не следует интерпретировать как универсальную оценку познаваемости идентичности.

Оценка локальна по соседним кадрам. При исчезновении пары с одним ID на обеих сторонах нет, поэтому восстановление траектории через невидимый промежуток не оценивается и не реализуется. Нулевая потеря сценария исчезновения не означает решение задачи реидентификации после окклюзии.

## Подтверждённое сравнение

На стандартном тестовом наборе выбранная конфигурация: `max_speed=5`, `max_area_change=.6`, `max_shape_change=.9`.

| Показатель | Базовая 5А | Подобранная |
|---|---:|---:|
| Верные соответствия | 22 | 27 |
| Ложные соответствия | 0 | 0 |
| Пропущенные соответствия | 14 | 9 |
| Из них решительно отвергнутые | 8 | 3 |
| Обоснованная неопределённость | 6 | 6 |
| Неопределённость вне неоднозначных переходов | 0 | 0 |
| Потеря | 8 | 3 |

Улучшение получено на перемещениях (два дополнительных верных соответствия) и изменении формы (три). Увеличение размера остаётся причиной трёх пропусков: расширение допуска площади также допускает ложное объединение в сценарии замены, поэтому обучающая функция потерь сохраняет `.6`. Пересечения остаются `unknown_identity`. Для двух одинаковых независимых траекторий и исчезновения изменения метрик нет.

Отрицательный контроль реализован тестом: обучение и валидация только на увеличении размера (`seed=11` и `101`), тест только на замене (`211`). Более мягкая конфигурация даёт ложное соответствие, тестовая потеря становится хуже базовой, и отчёт возвращает `worse`. При поиске только среди базовых параметров возвращаются `baseline_retained` и `no_improvement`. Ни один из этих исходов не подменяется объявлением успеха.

## Память и запуск

```powershell
python -m experiments.memory.identity_learning demo
python -m experiments.memory.identity_learning demo --db identity-study.sqlite3
```

Демонстрация выводит таблицу метрик до/после, выбранные параметры, потери по сценариям, решения при изменении формы и сохраняемую неопределённость пересечения. По умолчанию используется SQLite `:memory:`; `--db` сохраняет опыт в файл.

`identity_training_dataset` хранит роли частей, seeds, версию генератора, контрольную разметку и ссылки на исходные кадры. Контрольная разметка не попадает в `observation.payload` и компоненты. `identity_parameter_study` хранит версии 5А/5Б, исходную и выбранную конфигурации, перебранные кандидаты, формулу потерь, результаты обучения, валидации и теста, сравнение с базой и хеши содержания выборок. Связи `evidence` ведут к кадрам. Это разделение потока данных, не механизм разграничения прав доступа к SQLite.

`persist_experiment(memory, result, splits)` проверяет соответствие отчёта данным и переиспользует завершённую запись при повторном сохранении. Демонстрация применяет обе конфигурации явно к тем же сохранённым кадрам; прежние события 5А не изменяются. Схема SQLite и существующие алгоритмы 5А/discovery остаются прежними.

Тесты: `python -m unittest discover -s tests -v` и `python -m unittest experiments.discovery experiments.discovery_symbolic experiments.discovery_transfer -v`.
