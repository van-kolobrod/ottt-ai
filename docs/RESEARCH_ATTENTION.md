# Исследовательское внимание: эксперимент 4А

Модуль [`attention.py`](../experiments/memory/attention.py) реализует конечный цикл «память → кандидаты → оценка → выбор или отказ → производное событие». Он формирует исследовательские вопросы; автоматическая проверка гипотез и открытие законов в него не входят.

## Происхождение и границы

Использован реально доступный локальный исходник `C:\OTTT-AI\ottt_attention_v1.py`, SHA-256 `87892dfed74deea061640bce30cd320a0ca7807f371e9d852d3c05eb0f26aa5c`. Из него адаптированы прозрачная взвешенная оценка, отбор по минимальным требованиям, порог отказа и детерминированное разрешение равенства оценок по ID. Локальный исходник не изменён. Его внешний ввод готовых кандидатов и пяти оценок заменён автоматическим построением вопросов и расчётом характеристик из записей памяти.

Вход — все события `observation`, включая архивные, с плоским словарём `payload.features`. Поддерживаются конечные числа, строки и логические значения; `null`, вложенные объекты и списки пропускаются. Числа `1` и `1.0` эквивалентны; логические значения отличаются от чисел. Необработанная ASCII-сетка и производные события `perception` автоматически не преобразуются в такой словарь. ID неподдержанных наблюдений сохраняются в решении, чтобы граница входа была явной.

Пример записи:

```python
memory.add("observation",
           {"object_id": "sensor-stand-1", "features": {"state": "open", "temperature": 20}},
           source="instrument-A", occurred_at="2026-11-04T10:00:00Z")
```

`object_id` задаётся источником. Время события берётся из `occurred_at`, а не из времени записи в память. Для сравнения времён требуются ISO timestamps с часовым поясом. Семантика свойств, единицы измерения, достоверность источника и точность часов пока не устанавливаются автоматически.

## Генерация кандидатов

| Тип | Измеримое основание | Возможная проверка |
|---|---|---|
| `repeated_property` | Одинаковое значение одного признака как минимум в двух разных наблюдениях | Новые независимые измерения, сравнение частот по объектам, времени и источникам |
| `rare_combination` | Пара значений встречается не чаще 1/4 сопоставимых наблюдений; сопоставимых наблюдений минимум четыре; каждое значение отдельно встречается минимум дважды; наблюдаемая совместная частота меньше ожидания при независимости | Новые парные измерения, проверка независимости и смещения выборки |
| `potential_contradiction` | Разные значения одного признака при одинаковом `object_id` | Проверка идентичности, контекста, точности времени, надёжности источников и повторное измерение |

Для редкой комбинации с маргинальными частотами `a`, `b` и объёмом сопоставимой выборки `M` ожидаемое число совместных появлений равно `a*b/M`. Это только модель сравнения: малая выборка не устанавливает статистическую значимость и не доказывает независимость свойств. В свидетельства кандидата входят и совпадения, и наблюдения сравнения; `support_ids` отдельно указывают совпадения.

Различие значений в разные моменты получает `possible_state_change_between_times`. Отсутствие надёжно сопоставимого времени, отсутствие источника и одинаковый источник также фиксируются в `uncertainty`; такие кандидаты не допускаются к выбору. Совпадение момента и разные названия источников позволяют поставить вопрос о расхождении источников, но не превращают его в установленное противоречие. Различия между разными объектами вообще не порождают кандидата этого типа.

## Оценка

Пусть `N` — число наблюдений с поддерживаемыми признаками, `E` — число наблюдений в свидетельствах кандидата. Оценки лежат в диапазоне `[0,1]`; точные формулы, исходные счётчики и вклады каждого слагаемого сохраняются в решении.

| Показатель | Способ вычисления |
|---|---|
| Новизна | Повторение: `1-support/N`; редкая пара: `1-support/expected`; расхождение: `1-dominant_value_count/object_feature_count` |
| Повторяемость | Повторение: `support/N`; редкая пара: `min(a,b)/M`; расхождение: `2/object_feature_count` |
| Объяснительная сила | Предварительный показатель охвата: `E/N` |
| Проверяемость | Предварительный показатель происхождения: доля свидетельств с указанным источником |
| Свидетельства | Число различных непустых ID источников, делённое на `E`; независимость не доказывается |
| Доступность проверки | `N/(N+E)`; стоимость оценивается числом записей для просмотра `E` |
| Релевантность цели | Доля имён признаков кандидата, явно включённых в `goal.features` |

Новизна здесь означает редкость/разнообразие внутри текущей выборки, а не историческую неизвестность. Охват не является доказанной объяснительной силой; происхождение не гарантирует экспериментальную проверяемость; просмотр записей не оценивает стоимость внешнего эксперимента. Эти ограниченные показатели требуют последующей проверки качества приоритизации.

| Режим | Новизна | Повторяемость | Охват | Проверяемость | Свидетельства | Доступность | Релевантность |
|---|---:|---:|---:|---:|---:|---:|---:|
| `exploratory` | .25 | .20 | .20 | .15 | .10 | .10 | 0 |
| `goal_directed` | .05 | .05 | .10 | .10 | .10 | .05 | .55 |

Веса, пороги, типы вопросов и шаблоны проверки заданы разработчиком. Оценка — сумма взвешенных показателей, **не вероятность истинности**. Порог выбора по умолчанию `.60`; нужны минимум два разных ID наблюдений, проверяемость не ниже `.35`, охват не ниже `.25`, достаточный временной/источниковый контекст для расхождений. Целевой режим требует непустой `goal.features` и ненулевой релевантности. Естественный язык задачи автоматически не интерпретируется. При равенстве приоритетов используется порядок стабильных ID.

## Память и запуск

```python
from experiments.memory.attention import attend
from experiments.memory.store import Memory

memory = Memory("experience.sqlite3")
try:
    free_decision = attend(memory)
    goal_decision = attend(memory, mode="goal_directed", goal={"features": ["temperature"]})
finally:
    memory.close()
```

Событие `research_decision` хранит кандидатов, оценки, формулы, веса, пороги, выбранный ID либо отказ, основания, версию алгоритма и список входных наблюдений. Связи `considers` ведут к первичным наблюдениям. Наблюдения не изменяются; архивирование не исключает их из анализа. Решение и ссылки записываются одной транзакцией через существующий `Memory.add(..., links=...)`, без изменения схемы БД.

Ключ решения учитывает исходные события, режим, цель, версию алгоритма и конфигурацию. Повторный запуск, включая повторное открытие БД, возвращает существующее событие. Новые наблюдения, другая цель/конфигурация или версия дают новое событие; предыдущие события сохраняются. Блокировка SQLite сериализует проверку ключа и запись.

Демонстрация: `python -m experiments.memory.attention demo`. По умолчанию используется временная память `:memory:`; `--db` задаёт SQLite-файл. Демонстрация добавляет пример наблюдений, поэтому повторный запуск с одним файлом добавляет новые первичные события; идемпотентен именно `attend` на неизменном наборе событий. Свободный режим выбирает редкую комбинацию, целевой — исследование признака `target`.

Тесты: `python -m unittest discover -s tests -v`; тесты discovery: `python -m unittest experiments.discovery experiments.discovery_symbolic experiments.discovery_transfer -v`.

Модуль выполняет полный просмотр памяти и перебор пар признаков/записей об объекте. Он предназначен для небольших экспериментов; не выполняет внешние действия, сам не проводит измерения и не запускает бесконечный исследовательский цикл.
