# Числовой исследовательский цикл: эксперимент 4Б

[`research.py`](../experiments/memory/research.py) реализует конечный воспроизводимый цикл «числовые наблюдения → вопрос → конкурирующие формулы → прогнозы → проверка → память». Он использует публичный `Researcher.hypotheses()` из `discovery_symbolic.py`; существующие discovery-алгоритмы и критерии внимания не изменены. `discovery_transfer.py` исследован как пример раздельных калибровки и проверки, но его перенос между доменами не включён в этот цикл.

## Вход и границы исследования

```python
from experiments.memory.store import Memory
from experiments.memory.research import research

memory = Memory("experience.sqlite3")
try:
    for x in range(1, 9):
        memory.add("observation", {
            "series_id": "example", "features": {"x": x, "y": 2*x}
        }, source="synthetic_example")
    run = research(memory, series="example")
    result = memory.get(run["result_ids"][0])
finally:
    memory.close()
```

Принимаются наблюдения с двумя конечными числами в `payload.features`. Логические значения, отсутствующие и нечисловые признаки пропускаются. Сырой ASCII-сигнал автоматически не преобразуется в числа. `series_id` изолирует наборы данных; отсутствие этого поля означает `default`. Имена независимой и зависимой переменных по умолчанию — `x` и `y`, их можно явно изменить параметрами `independent` и `dependent`. Направление зависимости задано контрактом данных, причинность не устанавливается.

Наблюдения, включая архивные, упорядочиваются по `recorded_at, id`. Это хронология записи, а не реконструкция времени явления. В первом запуске первые `max(3, floor(2*N/3))` записей, но не более `N`, образуют обучающую часть; остальные — проверочную. Разделение сохраняется в вопросе. Внимание, параметры и выбор формулы используют только обучение; значения проверочной части при этом недоступны подбору.

После формирования гипотез обучающая часть, параметры и порядок кандидатов заморожены. Новые наблюдения той же серии добавляются к накопленной проверочной части. Они не используются для переподбора. Если начальных обучающих записей меньше трёх, сохраняется `inconclusive`; при поступлении достаточных данных создаётся новый вопрос с новой обучающей частью, а предыдущий сохраняется. Если обучающих записей достаточно, но семейство не позволяет идентифицировать зависимость (например, все `x` одинаковы), результат остаётся `inconclusive`; новый подбор требует отдельного явно заданного исследования/конфигурации.

## Вопрос, кандидаты и выбор

К существующим функциям `generate_candidates()` и `choose()` внимания передаётся только обучающая часть. Используется режим `goal_directed` с именами двух переменных. Если выбранный кандидат относится только к ним, вопрос о числовой зависимости связывается с ним через `attention_decision` и `question_origin=attention_adapter`. Иначе минимальный адаптер формирует такой вопрос непосредственно из числовых записей (`numeric_dependency_adapter`). Формула при этом не задаётся адаптером.

Используется существующее ограниченное семейство выражений: `x`, `1`, сложение, умножение и деление в грамматике `discovery_symbolic.py`. Для каждого выражения `f(x)` подбираются параметры `y = a*f(x)+b` по обучению. Ранжирование: нормированная обучающая MSE плюс `1e-12 * complexity`. Нормировка MSE: деление на `max(1, max(abs(y_train)))**2`. Преимущество обучающего совпадения не считается доказательством закона.

По умолчанию сохраняются три лучших кандидата, различающихся прогнозами на фиксированных вычислительных пробах `x=(.73,1.31,2.71,5.13)` после округления до девяти знаков. Это фильтр эквивалентных вариантов `a*f(x)+b`, а не доказательство алгебраической эквивалентности. Пробы не являются измеренными данными и не берутся из holdout. Для выполнения гипотезы выражение восстанавливается по имени из существующей грамматики, без `eval` сохранённого текста.

`selected_hypothesis_id` всегда указывает на лучшую гипотезу по обучению. Проверочные результаты не используются для повторного ранжирования. Проверяются все сохранённые конкуренты, поэтому результат каждого остаётся видимым, включая опровержения.

## Критерий проверки и состояния

Для каждой проверочной точки сохраняются ID наблюдения, `x`, фактическое `y`, прогноз, знаковая и абсолютная ошибки, допуск и результат сравнения. Допуск по умолчанию: `1e-8 + 1e-6*abs(actual_y)`. Параметры конфигурации и критерий сохраняются в каждом результате.

| Состояние | Событие и смысл |
|---|---|
| `proposed` | `hypothesis`: формула и параметры предложены по обучающим данным |
| `testing` | `hypothesis_check`: начинается проверка фиксированного набора данных |
| `supported` | `hypothesis_result`: проверочных точек минимум две, все ошибки в пределах допуска |
| `refuted` | `hypothesis_result`: точек достаточно, но есть ошибка вне допуска либо выражение не определено/не даёт конечного прогноза |
| `inconclusive` | `hypothesis_result`: проверочных точек меньше двух; либо `research_result`, если гипотезы невозможно сформировать |

Недостаток проверочных данных имеет приоритет над другими исходами: даже ошибка на единственной проверочной точке не даёт `supported` или `refuted` по этому критерию. Это консервативное правило данного эксперимента. `supported` означает поддержку только проведённой проверкой; универсальная истинность и устойчивость к другим распределениям данных не установлены.

Если новые наблюдения меняют результат, создаётся `hypothesis_revision` с прежним и новым статусами, ссылками на оба результата и ID новых свидетельств. Даже при неизменном статусе новый набор проверки создаёт новый результат. Исходная гипотеза остаётся `proposed` в историческом событии; актуальная оценка читается из последнего `hypothesis_result`. Старые результаты не переписываются и не удаляются.

## Память, воспроизводимость и ограничения

Вопросы, гипотезы, начало проверки, результаты и пересмотры — отдельные производные события существующего журнала SQLite. Каждое ссылается на первичные числовые наблюдения через `evidence`; дополнительные связи соединяют проверки и пересмотры. Версия алгоритма и вычисляемый ключ события обеспечивают повторное использование записей при неизменном входе. Сохранённая гипотеза переиспользуется после повторного открытия БД. Запись каждого события вместе со ссылками атомарна через существующий `Memory.add(..., links=...)`; повторный запуск может завершить прерванную последовательность без повторного создания готовых событий.

Модель применима к конечным числовым входам выбранной серии, на которых выражение определено. В событии гипотезы сохраняются диапазон обучающих `x` и ограничения области; проверка за этим диапазоном отмечает лишь успех/неуспех конкретных прогнозов. Нет автоматического управления внешними измерениями, причинного вывода, универсального выбора переменных, оценки статистической значимости и гарантии нахождения выражения вне ограниченной грамматики. Грамматика, порядок разделения, число конкурентов, фильтр эквивалентности и допуски заданы разработчиком; формула, параметры и ошибки получаются вычислительно из данных.

## Демонстрация и тесты

`python -m experiments.memory.research demo` выполняет изолированные сценарии в SQLite `:memory:`:

- Устойчивая зависимость: обучение `x=1..5`, проверка `x=6..8`, алгоритм выбирает `y=2x` и получает `supported`.
- Пересмотр: добавление `(9,999)` переводит эту гипотезу в `refuted`, сохраняя прежнюю поддержку.
- Ложное продолжение: то же обучение, но проверочные `y=2x+10`; выбранная формула получает `refuted`.
- Недостаток данных: обучение `x=1..3`, проверка только `x=4`; результат `inconclusive`.

Тесты памяти и цикла: `python -m unittest discover -s tests -v`.
Тесты discovery: `python -m unittest experiments.discovery experiments.discovery_symbolic experiments.discovery_transfer -v`.
