# Идентичность сущностей во времени: эксперимент 5А

[`identity.py`](code/experiments/memory/identity.py) сопоставляет компоненты соседних ASCII-кадров и сохраняет гипотезы индивидуальной идентичности. Используется существующий `spatial.perceive_event()` и четырёхсвязное выделение компонентов из `perception.py`. Совпадение формы и внутренний ID не доказывают, что физический объект тот же самый.

## Кадры и измерения

```python
from experiments.memory.store import Memory
from experiments.memory.identity import add_frame, track

memory = Memory("frames.sqlite3")
try:
    frames = [
        add_frame(memory, "#....", "2026-11-04T00:00:00Z", frame_id="f0"),
        add_frame(memory, ".#...", "2026-11-04T00:00:01Z", frame_id="f1"),
        add_frame(memory, "..#..", "2026-11-04T00:00:02Z", frame_id="f2"),
    ]
    result = track(memory, frames)
finally:
    memory.close()
```

Кадр — первичное событие `observation` с исходным `signal`, отдельной меткой `frame_id`, источником и `occurred_at`. ID события используется как ссылка на кадр; он отличается от локального ID компонента и ID предполагаемой сущности. Исходная строка сохраняется без изменения. Повторная регистрация сигнала создаёт новое наблюдение; идемпотентен повторный анализ уже зарегистрированных кадров.

Время задаётся ISO timestamp с часовым поясом и нормализуется при сравнении; порядок кадров должен быть неубывающим, повторение одного ID кадра и обратный порядок отклоняются. Система координат предполагается общей и неподвижной, размеры ячеек и масштаб — сопоставимыми. Движение камеры и изменение масштаба не компенсируются.

Для каждой пары компонентов сохраняются расстояние между центроидами, временной интервал, относительное изменение площади, габаритов, контуров, изменение символа и вклад в стоимость. Площадь — число ячеек. Контур представлен множеством занятых ячеек после переноса начала bounding box в `(0,0)`; отдельное выделение границы не выполняется. Размеры и форма не являются предметными категориями.

## Критерии и параметры

Все перечисленные параметры настраиваются словарём `config` у `track()` или `match_components()`; конфигурация сохраняется в событии сопоставления.

| Параметр | По умолчанию | Смысл |
|---|---:|---|
| `max_speed` | 3 | Максимум ячеек в секунду по расстоянию центроидов |
| `min_interval` | .001 | Минимально разрешимый временной интервал, секунды |
| `max_interval` | 5 | Максимальный интервал для непрерывного соответствия, секунды |
| `max_area_change` | .6 | Максимум `abs(area1-area2)/max(area1,area2)` |
| `max_shape_change` | .6 | Максимум `1-IoU` множеств занятых ячеек, выровненных по bounding box |
| `max_pair_cost` | .8 | Максимальная взвешенная стоимость допустимой пары |
| `ambiguity_margin` | .15 | Допустимая разница суммарной стоимости глобального назначения с лучшим |
| `max_components` | 6 | Предел полного перебора на кадр; разрешённая настройка от 1 до 7 |

Стоимость пары — сумма пяти показателей с весами из `config.weights`:

- `distance`, вес `.45`: расстояние центроидов / (`max_speed * interval`).
- `area`, вес `.15`: относительное изменение площади.
- `dimensions`, вес `.15`: среднее относительных изменений ширины и высоты, каждое относительно максимума двух размеров.
- `shape`, вес `.20`: `1-IoU` перенесённых множеств ячеек.
- `signal`, вес `.05`: 0 при одинаковых символах, 1 при разных.

Веса должны быть конечными, неотрицательными и суммироваться в единицу. Символ влияет на стоимость, но не запрещает соответствие сам по себе. Ограничения скорости, площади и формы — жёсткие отсекающие условия. Стоимости и пороги — настройки разработчика, не вероятности истинности идентичности.

При одинаковых временных метках, слишком малом или слишком большом интервале возвращается `unknown_identity`. Деление на ноль не выполняется. При превышении лимита компонентов анализ пары останавливается с `unknown_identity`; жадная замена или усечение альтернатив не применяется.

## Глобальное назначение и неопределённость

Для небольшой пары кадров перебираются все частичные взаимно однозначные назначения по допустимым рёбрам. Сначала максимизируется число сопоставлений, затем минимизируется сумма стоимостей. Сохраняются все назначения максимальной мощности в пределах `ambiguity_margin` от лучшего. Обе стороны каждого назначения уникальны; один компонент не может достаться нескольким траекториям.

Дополнительно сохраняются допустимые обмены визуально неразличимых компонентов, даже если их стоимость дальше от оптимальной: все затронутые компоненты должны иметь одинаковые символ, габариты и перенесённые множества ячеек. Это консервативное правило: если два одинаковых объекта способны поменяться местами за указанный интервал в рамках скорости, меньшая дистанция не доказывает единственную идентичность. Предсказание скорости/инерции по предыдущим кадрам пока не используется.

| Статус пары | Основание |
|---|---|
| `same_entity` | Пара присутствует во всех сохранённых глобальных назначениях и проходит ограничения |
| `different_entity` | Пара нарушает условия либо исключена всеми сохранёнными глобальными назначениями |
| `unknown_identity` | Пара встречается только в части сохранённых назначений либо временной контекст недостаточен |

Отрицательный статус отвергает конкретное соответствие в рамках модели и порогов, а не доказывает различие объектов во всех возможных моделях. Отсутствующий или неоднозначный компонент сохраняется в списке несопоставленных. Отсутствие наблюдения не означает уничтожения.

## История и память

`identity_matching` хранит конфигурацию, признаки, стоимости и основания всех пар, глобальные альтернативы и ссылки на исходные кадры и события восприятия. `identity_hypothesis` отдельно хранит поддержанную последовательность `(frame event ID, time, component ID)`, предполагаемый `entity_id`, подтверждающие признаки и изменения текущего перехода; предыдущая гипотеза доступна по `previous_hypothesis_id`. Каждый следующий шаг создаёт новую запись, не переписывая историю.

Для несопоставленных или неоднозначных наблюдений создаётся отдельная гипотеза `unknown_identity` с `entity_id=null`, альтернативами и ссылками на предыдущие известные гипотезы. Новые постоянные ID в этом случае не выдаются. При первом поддержанном переходе ID сущности вычисляется из исходного кадра, компонента, конфигурации и версии алгоритма; это техническая метка предполагаемой траектории, не доказательство существования сущности.

Неопределённость разрывает автоматическое продолжение траектории. Если позднее возникает новая однозначная пара, она начинает новую гипотезу. Восстановление после окклюзии, слияние, разделение, причинность и объединение траекторий из разных независимых запусков не реализованы. Для продолжения последовательности нужно передавать её сохранённый префикс вместе с новыми кадрами; анализ произвольного суффикса не гарантирует прежние ID.

Все производные события имеют ссылки `evidence` на исходные кадры. Версия алгоритма, конфигурация, ID событий восприятия и содержание вывода входят в ключи событий. Повторный анализ той же последовательности после повторного открытия БД переиспользует записи; добавление кадров сохраняет прежний префикс. Исходные наблюдения и старые гипотезы не изменяются.

## Демонстрация и проверки

Ограниченный подбор параметров по независимой разметке описан в [эксперименте 5Б](IDENTITY_LEARNING.md). Он использует этот алгоритм без изменения базовой конфигурации; новые параметры применяются явно.

`python -m experiments.memory.identity demo` показывает перемещение, две одинаковые независимые траектории, сближение с неразличимым обменом, исчезновение и небольшое изменение формы. В сценарии обмена две одинаковые конечные картинки могут означать как сохранение мест, так и смену мест между кадрами; возвращаются альтернативы и неопределённость.

`python -m unittest discover -s tests -v` включает сценарии, глобальную уникальность, случай ошибки жадного выбора, одинаковое время, ограничение скорости, изменение символа, сохранность свидетельств, идемпотентность и повторное открытие БД. Discovery-тесты запускаются отдельно: `python -m unittest experiments.discovery experiments.discovery_symbolic experiments.discovery_transfer -v`.
